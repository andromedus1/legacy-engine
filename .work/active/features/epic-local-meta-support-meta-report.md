# Local meta report generation (one-command, private/local)


# Meta report generation as a local engine capability

Make the local-field-vs-global-corpus comparison report a first-class engine output
generated by one command, for **private/local use** — not for public publishing. (The
earlier public Boulder report was retired 2026-06-29; see the `boulder-meta-public-report`
memory. This item keeps only the engine-side ideas, decoupled from any sharing/Pages step.)

## Two ideas worth keeping

- **Report-regen CLI.** A command that regenerates the comparison report HTML from engine
  analysis in one step — global `report meta` + `analytics.match_results` MWP + a supplied
  local field file — instead of the manual edit/copy/deploy dance. Output is a local HTML
  file (e.g. under `decks/`); no publish step.
- **Generalize beyond Boulder.** The same machinery (local field file + global corpus)
  produces a report for *any* meta, not just Boulder. Parameterize on the input field file
  so a new local scene is just a new `--field <file>` rather than a code change.

## Honesty line (carries over)

Prevalence is reliable; MWP samples are thin (CIs overlap). Any automation must keep
sample sizes + Wilson CIs visible and never overclaim win rates — same gate the engine's
other advisory surfaces hold.
