# Spec: legacy-engine

> *Why* this exists → [VISION.md](VISION.md). *How* it's built → [ARCHITECTURE.md](ARCHITECTURE.md).

## Capabilities

Grouped by pillar. **Built** = shipped; **Building** = in flight now (tracked as an epic in
`.work/active/epics/`); **Later** = deferred to a subsequent pillar.

### Pillar 1 — Meta & Performance
- **[Built] Ingest card data** from Scryfall (oracle text, types, mana cost, CMC, colors, legality) — the card dimension, shared shape with edh-engine.
- **[Built] Ingest card prices** from Scryfall default_cards bulk (per-printing USD prices → `card_prices` DuckDB table; `PriceQuote.all_null` is the honest-null signal).
- **[Built] Ingest tournament results** from the fbettega decklist cache (MTGO Challenges + Melee paper events) — the edhtop16 analog.
- **[Built] Parse archetypes** — label each decklist into the community taxonomy via ported MTGOFormatData rules.
- **[Built] Sub-archetype variant tagging** — classify each deck's variant (e.g. "Bauble") by card-presence registry; drives `report meta --by-variant` and `generate consensus --variant`.
- **[Built] Compute the metagame** — tier list, meta-% under multiple definitions (raw count / top-cut presence / win-rate-weighted), with explicit online/paper/blend labeling; venue divergence (online vs paper share spread via `report meta --venues`).
- **[Built] Matchup matrix** — N×N archetype win-rate table computed from cache standings, with sample-size + confidence per cell.
- **[Built] Trends & regime shifts** — meta evolution across banned-list announcements (the Entomb-ban-style step change as a first-class view).
- **[Built] Sub-archetype split** — `report subgroup` partitions an archetype's pool by card-presence signature and shows per-subgroup matchup deltas and card divergence.
- **[Built] Data-driven subarchetype resolution** — a two-level taxonomy (parent archetype × discovered subarchetype). `discover` clusters a parent's decks on the flex band (TF-IDF/count → reduce → HDBSCAN), validates each split through a statistical gate (resampling stability / prediction strength) **and** the domain gate (both camps ≥ evolving tier + signature-card divergence, guarding against clustering double-dipping) **and** a temporal gate (Gate C: camps whose median dates separate ≥120 days flag "camps may be list generations"; pools default to the parent's stable era with `--all-pool` escape; per-camp median date + %current surfaced), auto-names it, and stages it as a **candidate**; `promote` moves a confirmed split into the curated variant registry (discovery never auto-rewrites the taxonomy). The variant dimension is then an **opt-in overlay** on the matchup matrix and per-card win-rate: default output is byte-identical, and variant-conditioned cells reuse the existing Beta-Binomial shrinkage + speculative/evolving/established tiers so thin camps surface labeled, never hidden or blended. Also fixes cross-archetype contamination in `report cards` (archetype/variant-scoped denominator + honest-degrade sign-conflict warning) and surfaces subgroup win% in `report subgroup`. See `docs/briefs/subarchetype-discovery.md`.
- **[Built] New-card surfacing + speculation** — `report new-cards` lists the card names added in the most recent `refresh cards` diff-ingest run (the "what's new to test this week" surface); `report speculate` (and `report speculate --new`) forecasts a pre-data card's fitness using `interaction_facts` + role-filtered analogues, always labeled `PRE-DATA FORECAST`.
- **[Built] Player-strength scoring** — `identify suggest|strong|track`: alias resolution, confidence-gated strength records (min events + tier + win-rate), per-regime archetype history.
- **[Built] Ban-affectedness report** — `report affectedness --archetype NAME` explains which bans drove an archetype's `valid_since`, with per-ban-event adoption rates and provenance scope.
- **[Built] Per-entity stable-era detection** — `eras run` detects each archetype's (and qualifying camp's) era boundaries from the corpus itself: presence cliffs/ramps (bans/releases, trigger card named), composition change-points (ruptures kernel CPD + selection-corrected permutation p-values), play-rate share shifts, win-rate corroboration; candidates pass fleet-wide Benjamini–Hochberg FDR + a 30-deck era floor; thin camps inherit their parent's boundaries. Boundaries persist in the rebuildable `entity_eras` table with ban/release/unattributed attribution (±14d; corpus-first-seen release fallback). `eras list|explain` surface stable_since + the full per-boundary derivation; `eras confirm` appends a confirmed disturbance to the curated `BAN_EVENTS` JSON (the drift-alarm → human-confirm → regime-heal loop). A BOCPD drift alarm flags high-share entities whose recent share behavior implies an era break with no matching announcement — "possible unregistered B&R change" — loudly, without moving any numbers.
- **[Built] Stable eras are the DEFAULT windowing everywhere** — the adaptive matchup matrix sources each cell over `[max(stable_since(a), stable_since(b)), now)` (era → parent-era → ban-only fallback; undisturbed entities keep or widen to full history); the global field-composition window is detection-derived (max of the ban-regime start and the latest accepted high-share boundary, thin-degrade); consensus/card-frequency surfaces window at the entity's own era (camp-aware); every windowed figure names its window and triggering disturbance in `//` audit lines. With no era data the engine is byte-identical to the prior ban-only behavior, loudly labeled.
- **[Building] Recurrent stable-era evidence** — extend the current scalar suffix into versioned, certified disjoint interval sets. Candidate intervals are discovered without matchup outcomes, independently certified against prespecified configuration/context equivalence and affectedness/support guards, and consumed only through the pairwise intersection of both archetypes' interval sets. Reports preserve current-only, certified-expanded, and added-history views with event/component concentration. Expanded evidence remains diagnostic until leakage-free chained evaluation supports promotion. Historical report targets separate `data_until` from `knowledge_as_of`, so “today's model on old data” is never mislabeled as “as known then.” The evaluation-only validation surface for this work is now built under `advise recurrent-validation`; serving-time recurrent interval consumption remains separate from that validation workflow.
- **[Built] Hierarchical + cross-era cell shrinkage** — matchup cells shrink toward informative priors instead of flat 0.5: parent cells toward the subject's shrunk marginal; camp cells toward the leave-camp-out parent cell; thin post-boundary cells toward their own pre-disturbance value (labeled). Every cell carries `prior_source`; triple-display (shrunk% | raw% n=) is unchanged.
- **[Built] Trends movers digest** — `report trends --movers N` appends a biggest-movers table ranking archetypes by share delta between the two most recent ban-list regimes.
- **[Built] Superarchetype layer (strategy clusters)** — the third taxonomy level, above parent archetype. An offline `superarchetype` pass clusters archetypes by **maindeck core set** (cards at >=50% inclusion) **minus format staples** (cards core to >=30% of the cluster-defining archetypes — hard removal, since soft TF-IDF down-weighting fuses half the field into one "plays blue" cluster), using **Jaccard dissimilarity + average-linkage agglomerative** clustering cut by a pvpick-style descent retaining the largest branch that clears a multiscale-bootstrap **AU p-value > 0.95** (strict) AND a raw bootstrap-probability floor at scale 1.0; the trivial root is never a cluster and an unsupported definer becomes a labeled singleton rather than being forced into a family. Archetypes with >=30 decks and >=8 core cards may **define** a cluster; the long tail is **assigned** by mean Jaccard dissimilarity to a cluster's definers (average linkage's own criterion — a literal mean-vector centroid is metric-inconsistent with Jaccard); camps inherit their parent's cluster; a curated override layer wins by key and records the derived assignment it replaced. A subject's win rate against a cluster is a **random-effects (DerSimonian-Laird) inverse-variance pooled proportion** over the member cells, and the **`n_eff`** implied by its random-effects variance — never the raw pooled n — is what reaches `tier_for_sample()` and the display gate, so heterogeneity cannot buy a tier. Two gates plus two guards decide whether the pooled number may be claimed at all: concentration (`m_eff = 1/HHI >= 2.0` AND max member share <= 0.60; below that the cell is still served but labeled `dominated by <member>`), heterogeneity (I² <= 0.40 pool freely / 0.40-0.75 label `heterogeneous pool` / > 0.75 **refuse** the pooled number and show the member split), a direction/spread guard, and a minimum-computability rule. The engine exposes the cluster cell as a gated rung in the shrinkage chain between the leave-camp-out parent cell and the subject marginal, computed leave-opponent-out; the Best Call page currently consumes the typed ladder as labeled exploratory ledger/navigation evidence only, preserving archetype-level decision authority until the future-only benchmark passes. Intra-cluster matches count and carry an intra-cluster flag (the exact self-mirror is excluded from the rate with its n reported). **I² is one-sided evidence** — a high value is a reliable stop, a low value is never a certificate of exchangeability, and that caveat is a UI-level obligation. Cluster membership is recomputed per window but cluster identity stays stable across windows (measured co-membership agreement 0.957 across the Flow State and Candelabra disturbances); churn is a diagnostic. See `docs/briefs/superarchetype-aggregation.md` and `epic-superarchetype-layer`. `superarchetype run` previews by default; only an operator-reviewed `--promote` replaces the serving registry and DuckDB cache.

### Pillar 3 — Deck Generation
- **[Built] Consensus baseline** — modal-card aggregation over an archetype's in-window decks → legal exactly-60 + ≤15 de-duped list; `card_frequencies` primitive; `--variant/--players/--strong` pool filters.
- **[Built] Field-tuning (mode 2)** — greedy maindeck-flex swaps driven by field-weighted per-card×matchup value; no-signal fallback; maindeck-aware sideboard + per-matchup OUT/IN plans.
- **[Built] Export** — portable multi-target import text (Moxfield/Archidekt/MTGGoldfish/`.dec`); pure offline.
- **[Built] Gap discovery (mode 3)** — data-driven identification of under-explored cards/shells via `generate tune --discover` + adjacent-card PMI scoring.
- **[Built] Deck doctor** — `generate doctor` diagnoses a deck against the current field: flags stale includes, coverage gaps, and suggests targeted swaps.
- **[Later] Goldfish-validated candidate validation** — simulate candidates against projected field; depends on `goldfish/` pillar.

### Pillar 4 — Meta Attack / Advisory *(differentiator)*
- **[Built] Legacy meta-positioning score** — `Σ field_share(arch) × winrate(deck vs arch)` = expected WR vs the weighted field; user can supply a custom expected local field. Custom rows are `<share> <archetype> [count]`; `# current_regime_n: N` produces exact regime currency only when every row has a real count (or `# effective_n` supplies the complete basis), while undated aggregates explicitly report currency unavailable. Field-composition windows and adaptive matchup-cell windows are independent. Its candidate rows retain their established grounded/lean/imputation/inactive/unscorable evidence semantics; `--list-granular` remains an opt-in S_granular overlay.
- **[Built] Deck Rankings landing page** — `decks/deck-rankings.html`, generated by `scripts/refresh_best_call_ranking.py` and published by the full `scripts/refresh_decision_data.py` workflow. Performance is the complete-field weighted mean of per-cell posterior means (mirrors fixed at 50%); floor is the minimum non-mirror posterior mean, with its all-opponent minimum interval computed across seeded draws and the named toughest cell interval shown beside the point estimate. It shows independent performance/floor leaders and sorts, a Pareto map, prior-only/uncertain cells with provenance, and uses performance to break floor ties. New point estimates are not hidden by a support threshold; prior-only rows are labeled and excluded from calls.
- **[Built] Sideboard recommender** — recommends a sideboard package (up to 15) over the expected field as a two-stage **dedicated-core + hedge** solver: a saturating per-copy value model commits dedicated answers only up to their natural budget (so the package may be fewer than 15 and never pads with redundant copies), and optional hedge slots cover field uncertainty; models the anti-hate second order; collection-aware (`--collection`, `--owned-only`). Considering/bubble pool surfaces near-threshold candidates with residual coverage labels. Per-card element weight is impact-decomposed (`centrality × symmetry × castability`, gated multiplicative hard gates — the per-copy redundancy taper carries draw-probability separately) against each field opponent's derived-or-curated archetype linchpins (`advisory/linchpins.py`); `advise backtest` validates a recommended board against observed top-finisher sideboards as an empirical (non-causal) anchor.
- **[Built] "What to play" advisor** — proactive-vs-reactive and best-deck-vs-best-metagame-call framing over the current field; `ramp` vulnerability coverage included.
- **[Built] Standalone field read** — `advise field` surfaces field composition and vulnerability/hate-equity profile without requiring a deck argument; respects `--provenance` and window flags.
- **[Built] Provenance-filtered advisory** — `--provenance online|paper` is available on all `advise` leaves and on `report matchups`, filtering the matchup matrix and field by tournament provenance.
- **[Built] Head-to-head matchup lookup** — `report matchups --a <arch> --b <arch>` looks up a single directed matchup cell with Wilson CI, confidence tier, and speculative caveat where n is low.
- **[Built] Archetype-sweep backtest** — `advise sweep` batch-runs the board backtest over every eligible archetype against one shared field and mines ranked, root-cause-clustered scorer-vs-winners divergences (tier-gated, divergence-as-diagnostic — the engine's error map, never auto-calibrated into scores); `--json` adds copy-count histograms.
- **[Built] Future-only legacy ranking benchmark** — `advise benchmark plan|freeze|evaluate|run` evaluates its preregistered parent-archetype estimators through a frozen fold/B&R plan, raw pre-cutoff snapshots, hashed immutable predictions, non-overlapping whole-date 28-day folds reset/truncated at B&R (with a declared trailing field horizon at the boundary), frozen retrospective parent rules or dated contemporaneous taxonomy replay, classified deck-mass coverage, explicit support/censoring and player-sensitivity boundaries, proper scores, and stable event-block decision regret. It remains evidence for the mature benchmark surface and does not validate the new Deck Rankings projection.
- **[Built] Future-only recurrent evidence validation** — `advise recurrent-validation plan|freeze|evaluate|aggregate|proposal` is the cutoff-safe challenger workflow for recurrent-era evidence. `plan` validates the additive `src/legacy_engine/data/amplification/recurrent-evidence-future-v1.json` protocol against the exact hash-bound parent benchmark plan (`src/legacy_engine/data/benchmark/recurrent-parent-future-v1.json`) and stores it content-addressed. `freeze` seals one recurrent origin from a prebuilt cutoff snapshot, a typed five-stage refit chain (`discovery → certification → interval → structure → amplification`), and one full aligned forecast grid. `evaluate` scores predictive and decision evidence on a common future ledger with explicit future field counts. `aggregate` bundles exact origins and evaluations into promotable / inconclusive / negative / censored assessments across the direct recurrent estimators and additive amplification methods. `proposal` writes only an inert operator-review artifact for an exact promotable assessment. There is no `run`, no `latest` alias, and no auto-apply path; production remains unchanged until a separate reviewed promotion feature exists.
- **[Built] Experimental player-effect diagnostic** — `advise benchmark player-effect plan|freeze|evaluate|run` measures provenance-local identity accessibility and descriptive pilot stickiness, then compares a deck-residual control, partially pooled repeat-player intercept, and separately gated familiarity sensitivity on the benchmark's frozen future-only folds. Outcome-free participant forecasts are hashed before results open; player-aware/masked/neutral, cold-start, and online/paper strata remain visible. Reports are aggregate/privacy-gated and production-neutral. The strongest status is `candidate-for-promotion-study`, which still requires a separate reviewed promotion feature and never changes Agency, P(best), or the production estimator registry.
- **[Built] Collection-aware acquire plan** — `advise acquire` ranks priced buys by field-relevance × archetype-relevance; budget filter; redundancy/over-quantity flags.
- **[Built] Deck refresh** — `advise refresh` runs a full per-venue tuning pass (field-tuned maindeck + sideboard + primer); loudly labels thin/no-data matchups.
- **[Built] Matchup primer** — plain-speak per-matchup OUT/IN guide generated from the sideboard plan; `degraded=True` matchups are labeled reasoning-based, never fabricate numbers.

### Cross-cutting — Visualization & Reporting
- **Per-deck dashboard** — one self-contained page composing meta-share, the matchup spread (adaptive per-cell ban-aware matrix), trends across ban-regimes, positioning (best-call vs best-deck), and the consensus 60+15 list + primer, for any archetype.
- **Composable viz platform** — a Vega-Lite spec layer (hand-built spec builders + canonical theme via strip-and-inject + 12-col tile/layout; spec validity checked test-time via the real Vega-Lite compiler); any command emits composable tiles. Replaces the matplotlib chart export.
- **Dual output** — interactive self-contained HTML (vega-embed from CDN) + static PNG (vl-convert, no browser). Every chart carries the same confidence/labels as the text reports.

| **EntityEras** | An entity's detected era history | Per archetype/camp: boundaries (date, signals, magnitude, p-value, verdict, floor flag, attribution), drift-alarm state, the current `stable_since` fallback, and the intended normalized set of certified compatible intervals. Rebuildable from the corpus by `eras run`. |
| **EraCertificate** | A versioned decision that a historical interval is compatible with a reference interval | Records candidate/reference intervals, certification `as_of`, `certified | rejected | inconclusive`, feature/calibration versions, independent event partitions, semantic guards, adjusted equivalence evidence, support/concentration, and context overlap. Matchup outcomes are absent from discovery and certification. |
| **InteractionFacts** | A card's interaction classification | Pure function of card oracle text: graveyard reliance, counter-magic density, speed signals, free-spell flag. Consumed by speculation and vulnerability tagger; no DB dependency. |

| **Venue** | Online / paper provenance | Derived from fbettega source dir + URI host; used for per-venue meta-share splits and cross-venue divergence. |
| **DeckDefinition** | Deck-as-data for sim | *(Later)* card list + tagged roles (payoff/enabler/engine) + combo line + goldfish clock + confidence metadata. Mirrors edh-engine's YAML model. |
| **SideboardPackage** | A recommended sideboard (up to 15) | *(Advisory)* set of hosers with edges to the archetypes/hate-cards they attack, plus coverage score vs a field; each card labeled commit (dedicated core) vs insurance (hedge); may carry fewer than 15 with a marginal-coverage curve; carries per-matchup `MatchupPlan` (OUT/IN swaps). |
| **DeckDashboard** | A composed per-deck page | *(Viz)* a set of Vega-Lite tiles (meta-share, matchup spread, trends, positioning, consensus + primer) laid out on a 12-col grid and rendered to self-contained HTML + PNG. |
| **Inventory** | The user's owned cards | *(Personal)* owned card → quantity (+ printing/condition). Local, single-user now; schema designed cloud-ready for a later hosted surface. Makes advice buildable from what you actually own. |
| **UserDeck** | The user's own deck (a variant) | *(Personal)* a named, **versioned** 75 the user owns and plays — distinct from the inferred `Archetype`; cards may be allocated from `Inventory` (a deck vs the free binder). |

## Non-Functional Requirements

- **Reproducibility** — deterministic given inputs + seed; all external data pre-fetched and cached; the engine makes no network calls at analysis time (mirrors edh-engine).
- **Version-stamped legality** — every legality check resolves against a dated `BanListSnapshot`, so a 2024 deck that legally ran Psychic Frog validates correctly. A ban takes effect *on* its `banned_date`: a card is legal the day before and illegal on the date itself (`banned_date <= as_of` ⇒ banned). Banned-list data refreshed ~quarterly.
- **Uncertainty-qualified stats** — matchup cells and derived metrics carry sample size, intervals, priors, provenance, and confidence. Legacy surfaces may keep their documented low-n display gates; Deck Rankings keeps new point estimates visible, labels prior-only/uncertain cells, and uses no support threshold to suppress them. A **pooled** cell (superarchetype) still gates on its **effective** sample `n_eff`, not raw pooled n.
- **Source transparency** — every meta-% and matchup figure is labeled with its source, window, and online/paper/blend basis. No unlabeled headline numbers.
- **Resilience** — ingestion tolerates a single bad deck/event (catch, log, continue); mirror the community cache locally (it's fragile / community-run).
- **Portability** — local file storage, no DB or server required for MVP (storage revisited at /architecture if query patterns demand it).
- **Self-contained, offline viz output** — visualization output is local and needs no server: interactive HTML embeds `vega-embed` from CDN and opens directly in a browser; static PNG via `vl-convert` needs no browser/Chrome at all.
